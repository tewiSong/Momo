0312:
问题归因（根源）：
- 监督与决策不一致：正则/监督主要作用在 p_r（路由器分布）或 p_nn（基于 h_commit 最近邻），但真正选码是 y_soft∝p_r^β·p_nn^(1−β)。当 p_nn 很硬时，y_soft 被其主导，导致在 p_r 上的正则基本不起作用，码本使用塌缩。
- 强制最近邻：CE 把 p_r 拉向“最近邻硬标签”，抵消了熵正则和探索；Top‑K 过早稀疏化使大部分 code 进不了梯度通路。
- 教师链路主导梯度：teacher_align 权重大且无门控，训练长期在强噪声下进行。

本次改动（根源修复）：
1) 统一到几何教师分布 p_t：在模型前向中用 teacher_z（或无 teacher 时用 z_gt）到码本的距离构造 p_t=softmax(−‖teacher−code‖^2/T_t)，并用 p_r 与 p_t 融合得到真正用于选码的 y_soft（momo/models/gin_motif_vqmoe.py）。
2) 损失改为“对 y_soft 说话”：
   - KL：匹配 y_soft 和 p_t 的双向 KL；
   - 熵：直接对 y_soft 做熵正则；
   - 移除“最近邻硬标签”CE（默认权重=0，保留接口可选启用）(momo/train/losses.py)。
3) 两阶段训练：
   - Stage A 校准：仅训练 teacher_proj 对齐 z_gt，其他损失全部关闭；满足阈值后自动切到 Stage B（momo/train/pretrain.py）。
   - Stage B 联合：开启 recon/vq/commit 与路由相关损失；teacher 蒸馏两项按对齐门控线性升温。
4) 防早期强绑定与早稀疏：
   - commit_weight 线性升温（loss.commit_ramp_steps）；
   - Top‑K 延迟启用（router.topk_warmup_steps），早期使用期望向量避免梯度饥饿（momo/train/pretrain.py）。
5) 新监控：记录 y_soft 与 p_t 的 KL/熵，以及基于教师的 Top‑K 命中（momo/train/pretrain.py）。

配置变更：configs/pretrain_pcqm4mv2.yaml
- 新增 router.teacher_temperature、router.topk_warmup_steps、loss.commit_ramp_steps。
- 将 loss.ce_weight 默认改为 0.0，ent_weight 调整为 0.02。

预期效果：
- Stage A 里 val/train 的 teacher_align 快速下降并稳定到阈值以下；
- 进入 Stage B 后：
  - train/router/effective_codes 持续上升到 16–32；usage_unique_ratio > 0.4；
  - train/router/topk_nn_hit 不再贴近 1（更像 0.7–0.9，因存在探索）；
  - train/kl、val/kl 与熵曲线一致，验证不再显著高于训练；
  - recon 稳定下降，vq 平稳；commit 在 ramp 期平滑上升后稳定；
  - 总体 loss 不再被 teacher_align 主导。

文件清单：
- momo/models/gin_motif_vqmoe.py（p_t、融合与路由信息、Top‑K 动态）
- momo/train/losses.py（KL/ENT 作用到 y_soft，移除硬 CE）

根因（进一步确认）：
- 教师对齐不可达：教师链路为 SchNet 原子表征 → motif 均值池化 → 线性投影 → 标准化，仅含一阶统计，难以回归 z_gt 中的二阶量（长度/角度方差、惯性主轴特征值）。
- 数值放大：在 z_gt 的标准化空间对齐，个别维度 std 极小导致误差被成百上千倍放大，teacher_align 长期居高。
- 策略卡死：校准阶段把 recon/vq/commit 等主损失全部关闭，训练只能在对齐一条路上“干跑”，主干/路由/码本得不到纠错与驱动，形成闭环自锁。

本次修复（不弃用 3D 教师）：
1) 教师高阶聚合（表达阶次对齐 z_gt）
   - 在教师分支的 motif 聚合处，同时计算一阶均值 mu 与二阶方差 var（通过均方减均值平方），作为教师局部几何输入；再用 MLP(+LayerNorm) 投影至 7 维。
   - 代码：
     - momo/models/gin_motif_vqmoe.py:116–123（teacher_proj: Linear → MLP(+LN)，输入维=2×hidden）。
     - momo/models/gin_motif_vqmoe.py:211–219（mu/var 聚合并投影）。
   - 仍对 teacher_z 使用数据集统计的均值/方差标准化，以保持与 z_gt 的标尺一致。

2) 取消“硬门控”，主任务常开
   - 校准阶段不再把 recon/vq/commit/路由正则全部置零，仅关闭两项 teacher 蒸馏；commit 继续按 ramp 升温。
   - 代码：momo/train/pretrain.py:303–319。

兼容与运行提示：
- 旧 ckpt 不兼容（teacher_proj 结构变化）；不要从旧 ckpt 恢复。
- 若早期 p_t 仍偏尖，可将 router.teacher_temperature 提至 2–4，并保持 topk_warmup_steps 使早期用期望向量。

验证指标（预期变化）：
- teacher_align 明显下降（不再 1e5 级震荡）；
- train/router/effective_codes ↑，usage_unique_ratio ↑，train/ent > 0；topk_nn_hit 不再长期≈1；
- train/recon 稳定下降、train/commit 按 ramp 平滑上升，总损失不再被对齐项主导。

后续可选：
