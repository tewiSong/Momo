# 理想case:
用 联苯（biphenyl） 重新举例最合适。
联苯有两个苯环，通过单键连在一起。把每个苯环看成一个 motif。

这个分子里有什么
* motif A：左边苯环
* motif B：右边苯环
我们只看 motif A。

1. h_2d 是什么
h_2d 是 motif A 的 2D 上下文表示。
它包含的信息不是“标准苯环长什么样”，而是：
* 它是个芳香环
* 它通过单键连着另一个芳香环
* 连接位置在哪
* 周围邻居是谁
* 图结构上下文是什么
所以 h_2d 的含义是：
“这个苯环在整张 2D 分子图里处于什么上下文”

2. e_hat 是什么
router 看 h_2d，从 codebook 里选一个 prototype。
例如选出来的 e_hat 可以理解成：
“标准芳香环原型”
也就是一个粗粒度 3D 模板。
它只回答：
* 这类 motif 大概属于哪种几何模式
它不管这个联苯里两个环到底扭了多少度。

3. teacher_z 是什么
teacher_z 是 3D teacher 从真实 3D 构象里提取出来的 motif A 的表示。
对联苯来说，真实 3D 里最关键的是：
* 两个苯环通常不是完全共平面
* 会有一个扭转角
所以 teacher_z 表示的是：
“这个具体联苯里，左边这个苯环真实的 3D 状态”

4. Delta 是什么
expert 输入 (h_2d, e_hat)，输出 Delta。
它的作用是：
根据当前上下文，把“标准芳香环原型”修正成“联苯里的这个芳香环”
也就是：
* e_hat 说：这是一个标准苯环
* Delta 说：但因为它连着另一个苯环，所以要扭一点
所以 Delta 的含义就是：
上下文导致的类内偏移

5. z_hat 是什么
z_{hat} = e_{hat} + \Delta
含义：
模型预测出来的 motif A 的最终 3D-aware 表示
训练时要求：
z_{hat} \approx teacher_z

这个例子里，为什么必须同时有 e_hat 和 Delta
因为：
* 只靠 e_hat，你只能得到“标准芳香环”
* 但联苯里的苯环会因为另一个环的存在发生扭转
* 这个扭转不是 prototype 本身，而是上下文带来的变化
所以：
* e_hat = 粗原型
* Delta = 上下文修正
这才是你的方案真正想表达的东西。

一句话版本
对联苯里的左苯环：
* h_2d：它在整分子里的 2D 上下文
* e_hat：codebook 取出的“标准芳香环原型”
* Delta：因为连着另一个苯环而产生的扭转修正
* teacher_z：真实 3D 下这个苯环的表示
* z_hat = e_hat + Delta：模型预测的最终表示
这个例子比苯正确，因为它真的体现了“上下文修正 prototype”。

0402
- 问题1（冻结未生效且日志误导）
  - Δ 冻结仅覆盖主链路，MMM/Graph 分支未同步，冻结期 Δ 仍被间接训练。
  - TensorBoard 记录的是基础主损（losses['loss']），未包含叠加后的 MMM/Graph，总损曲线被低估。

- 问题2（定义冲突）
  - Prototype 路由输入用无上下文 h_motif_local，但监督目标 gt_nn_index/p_gt 来自 z3d_gt→zgt_proj 的最近邻（包含上下文效应）。
  - commit 拉近 h_motif_local→e_selected，而 CE/KL 拉向含上下文的 gt_nn_index，二者长期对冲。

- 修复1（冻结 Δ 全链路生效）
  - 模型前向新增 freeze_delta 开关，开启时强制 h_motif_enh=e_hat，z_pred=z_proto，delta=0，适用于主链路与所有辅助前向。
  - 训练脚本统一在 global_step<delta_freeze_steps 时对主链路、MMM、Graph 前向传入 freeze_delta=True。
  - 同步移除只改主链路 router_info 的手工覆写，避免不一致。

- 修复2（日志对齐实际优化目标）
  - train/loss 改为记录“最终反传总损”（含 MMM/Graph）。
  - 新增 train/loss_base 记录几何主损，便于分析对比；终端打印同步显示 total/base。

- 修复3（原型=上下文无关模板 的根源一致性）
  - 定义模板目标：z_template = zgt_proj − delta_latent_detach，用于计算 p_gt 与 gt_nn_index（仅模板、去上下文）。
  - CE/KL 对齐模板最近邻；commit 仍拉 h_motif_local→e_selected，二者语义一致，不再对冲。
  - 未引入兜底/容错路径，监督侧对 Δ 严格 stop‑grad，确保“Δ=上下文修正”。

- 受影响文件
  - momo/models/gin_motif_vqmoe.py：新增 freeze_delta；p_gt/gt_nn_index 基于 z_template；统一导出 delta。
  - momo/train/pretrain.py：所有前向在冻结期传 freeze_delta；训练日志记录 total 和 base。


0404
- 现象（来自最新预训练日志 runs/pretrain-pcqm4mv2-20260402-175612-gpu212-18）
  - 重建相关整体向好：train/val recon 大幅下降，loss_base 下降符合预期。
  - 路由与码本：top1_nn_hit 升至 ~0.655，但 effective_codes 从 ~128 降到 ~11（样本级 ~3.7），entropy 明显降低、balance 上升，exp_balance 偏高，显示码本和专家使用塌缩与负载不均。
  - 验证侧 ce 有小幅上行，提示目标定义存在残余对冲。

- 问题定位（定义与实现不一致）
  1) 模板监督未贯通：前向用模板 latent 计算 p_gt/gt_nn_index（基于 z_template=zgt_proj−Δ_detach），但 loss 里
     - vq 仍贴 zgt_proj；
     - proto_recon 仍用 z3d_gt 监督 z_proto；
     与“prototype=上下文无关模板”定义相悖，导致 commit 与 CE/KL 的长期拉扯，诱发码本使用度塌缩。
  2) freeze_delta 不纯：冻结期 p_gt/gt_nn_index 的模板仍含当步 Δ 的估计（虽 detach），冻结阶段的监督目标被 Δ 影响。

- 本次修复（不引入兜底/容错）
  - 统一模板监督：
    - vq 改为 MSE(e_target, z_template)；
    - proto_recon 改为 latent 空间 MSE(e_hat, z_template)（不再经由解码头生成模板几何）；
    - router_info 导出 z_template（模板 latent），不再导出 z_template_geom。
  - 冻结期纯化模板：freeze_delta=True 时，计算模板目标时显式用 Δ=0（不再使用 Δ 的当步估计）。

- 预期效果
  - 消除 commit 与 CE/KL 的定义对冲，原型聚类按“模板”收敛，码本使用度/熵回升、balance 下降，exp_balance 改善；
  - proto_recon 与 kl/ce 的下降趋势更一致；val/ce 上行趋势缓解；
  - 冻结阶段的监督更干净，有助于先学好原型再放开 Δ。

- 影响范围
  - 代码：momo/models/gin_motif_vqmoe.py（模板目标冻结感知与导出）、momo/train/losses.py（vq/proto_recon 改为模板监督与字段校验）。

- 验证建议
  - 重点观察：router/effective_codes、entropy、balance、exp_balance、proto_recon、kl/ce；
  - 对比冻结窗口内外的指标变化，确认模板监督与冻结纯化带来的改善。
